# Requirement: สั่งกาแฟผ่านมือถือที่โต๊ะ (Self-Order)

## ภาพรวม (Feature / User Story)

ลูกค้าที่นั่งอยู่ที่โต๊ะในร้าน สามารถสแกน QR code บนโต๊ะเพื่อเปิดเมนูบนมือถือของตัวเอง เลือกสั่งกาแฟ/เครื่องดื่ม และยืนยันคำสั่งซื้อได้เอง โดยไม่ต้องเรียกพนักงานมารับออเดอร์

## Functional Requirements

- ลูกค้าสแกน QR code ที่ติดอยู่บนโต๊ะเพื่อเปิดเมนูผ่านเว็บเบราว์เซอร์บนมือถือ (ไม่ต้องติดตั้งแอป)
- ระบบระบุหมายเลขโต๊ะโดยอัตโนมัติจาก QR code ที่สแกน
- ระบบแสดงเมนูเครื่องดื่ม พร้อมชื่อ รูปภาพ ราคา และตัวเลือก (เช่น ขนาด, ระดับความหวาน, ชนิดนม)
- ลูกค้าเลือกสินค้า ใส่ตะกร้า ปรับจำนวน และแก้ไข/ลบรายการในตะกร้าได้ก่อนยืนยัน
- ลูกค้ายืนยันคำสั่งซื้อพร้อมหมายเลขโต๊ะ โดยไม่ต้องเรียกพนักงาน
- ระบบส่งคำสั่งซื้อไปยังฝั่งร้าน/บาริสต้าแบบเรียลไทม์เพื่อเตรียมเครื่องดื่ม
- ลูกค้าสามารถดูสถานะคำสั่งซื้อของตนเอง (เช่น รับออเดอร์แล้ว / กำลังทำ / เสร็จแล้ว) ผ่านหน้าจอเดิม

## Non-functional Requirements

- ใช้งานได้บนเบราว์เซอร์มือถือทั่วไป (iOS Safari, Android Chrome) โดยไม่ต้องติดตั้งแอป
- หน้าเว็บโหลดเร็ว เหมาะกับการใช้งานผ่าน mobile data หรือ wifi ของร้าน
- รองรับลูกค้าหลายโต๊ะสั่งพร้อมกันในเวลาเดียวกันโดยไม่มีออเดอร์สับสนข้ามโต๊ะ
- ข้อมูลรับส่งระหว่างมือถือลูกค้ากับระบบต้องเข้ารหัสผ่าน HTTPS ตลอดทาง (รวมถึงหมายเลขโต๊ะ รายการสั่งซื้อ และ session/device identifier)

## Business Rules

- QR code 1 อันผูกกับหมายเลขโต๊ะ 1 หมายเลขเสมอ
- คำสั่งซื้อที่ยืนยันแล้ว ลูกค้าไม่สามารถแก้ไข/ยกเลิกเองได้ ต้องแจ้งพนักงานหน้าร้าน

## การคุ้มครองข้อมูลส่วนบุคคล (PDPA)

ระบบนี้เก็บ/ประมวลผลข้อมูลที่อาจเข้าข่าย **ข้อมูลส่วนบุคคล** ตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA) แม้ลูกค้าจะไม่ต้อง login/สมัครสมาชิกก็ตาม เนื่องจากข้อมูลบางอย่าง (เช่น session/device identifier ร่วมกับหมายเลขโต๊ะและเวลา) อาจนำไปสู่การระบุตัวตนลูกค้าคนหนึ่งได้โดยอ้อม ข้อมูลที่เกี่ยวข้องมีดังนี้:

- หมายเลขโต๊ะ + ประวัติคำสั่งซื้อ (รายการสินค้า, ตัวเลือก, เวลาสั่ง)
- Session/device identifier ของลูกค้า (เช่น session token, IP address, ข้อมูลเบราว์เซอร์) ที่ระบบเก็บไว้ชั่วคราวเพื่อเชื่อมสถานะออเดอร์กลับมาแสดงผลแบบเรียลไทม์บนมือถือเครื่องเดิม

### ฐานทางกฎหมายในการเก็บ/ประมวลผลข้อมูล (Lawful Basis)

- **ความจำเป็นเพื่อปฏิบัติตามสัญญา (Necessary for the performance of a contract)** — ใช้เป็นฐานสำหรับหมายเลขโต๊ะและรายการคำสั่งซื้อ เนื่องจากจำเป็นต่อการรับออเดอร์ ทำเครื่องดื่ม และแจ้งสถานะกลับให้ลูกค้า หากไม่เก็บข้อมูลนี้ระบบจะทำงานไม่ได้
- **ประโยชน์โดยชอบด้วยกฎหมายของผู้ควบคุมข้อมูล (Legitimate Interest)** — ใช้เป็นฐานสำหรับ session/device identifier และ IP address ที่เก็บไว้ชั่วคราว เพื่อความปลอดภัยของระบบ ป้องกันการปลอมแปลง/สั่งซ้ำซ้อนข้ามโต๊ะ และแสดงสถานะออเดอร์แบบเรียลไทม์ให้ถูกเครื่อง โดยไม่กระทบสิทธิของลูกค้าเกินสมควร
- ระบบ **ไม่ขอ/ไม่เก็บ** ชื่อ-นามสกุล เบอร์โทรศัพท์ อีเมล หรือข้อมูลระบุตัวตนโดยตรงอื่นใดในรอบนี้ เนื่องจากไม่ให้ login/สมัครสมาชิก จึงไม่จำเป็นต้องขอความยินยอม (consent) แยกต่างหากสำหรับข้อมูลส่วนนี้

### การแจ้ง Privacy Notice

- ต้องมีลิงก์ "ประกาศความเป็นส่วนตัว" (Privacy Notice) ที่เข้าถึงได้จากหน้าเมนูก่อนลูกค้ายืนยันคำสั่งซื้อครั้งแรก โดยระบุอย่างน้อย: ข้อมูลอะไรที่เก็บ, เก็บไปทำไม, ฐานทางกฎหมายที่ใช้, ระยะเวลาเก็บ, และช่องทางติดต่อเพื่อใช้สิทธิ
- ไม่จำเป็นต้องให้ลูกค้ากดยอมรับ (consent checkbox) ก่อนใช้งาน เนื่องจากใช้ฐาน contract/legitimate interest ไม่ใช่ consent — แต่ต้องแจ้งให้ทราบ (notice) ตามหลัก transparency ของ PDPA

### ระยะเวลาการเก็บข้อมูล (Data Retention)

- ประวัติคำสั่งซื้อ (รายการสินค้า/เวลาสั่ง/หมายเลขโต๊ะ) เก็บไว้เพื่อวัตถุประสงค์ทางบัญชี/สรุปยอดขายของร้าน ตามระยะเวลาที่ธุรกิจ/กฎหมายบัญชีกำหนด โดยไม่ต้องเก็บ session/device identifier ผูกไว้กับประวัติออเดอร์เกินความจำเป็น
- Session/device identifier และ IP address ที่ใช้แสดงสถานะออเดอร์แบบเรียลไทม์ ให้ลบทิ้งหรือทำให้ไม่สามารถระบุตัวตนได้ (anonymize) หลังจบรอบการใช้งานของโต๊ะนั้น (เช่น หลังลูกค้ารับออเดอร์ครบและปิดรอบโต๊ะ) — ดูรายละเอียดระยะเวลาที่ตกลงในสมมติฐานด้านล่าง

### สิทธิของเจ้าของข้อมูล (Data Subject Rights)

ลูกค้าในฐานะเจ้าของข้อมูลมีสิทธิตาม PDPA ที่ระบบ/ร้านต้องรองรับ (ผ่านช่องทางติดต่อพนักงาน/ร้าน เนื่องจากลูกค้าไม่มีบัญชี login ให้จัดการเอง) ได้แก่:

- สิทธิขอเข้าถึงและขอสำเนาข้อมูลของตน (เช่น ประวัติออเดอร์ที่เชื่อมโยงกับตนได้)
- สิทธิขอให้ลบหรือทำลายข้อมูล (right to erasure) เมื่อพ้นความจำเป็นในการเก็บ
- สิทธิขอถอนความยินยอม (ในกรณีที่อนาคตมีการเก็บข้อมูลโดยอาศัยฐาน consent เช่น เบอร์โทร/ระบบสมาชิก)
- สิทธิคัดค้านการประมวลผลที่อาศัยฐาน legitimate interest

### มาตรการรักษาความปลอดภัยของข้อมูลขั้นต่ำ (Minimum Security Measures)

- เข้ารหัสข้อมูลระหว่างรับส่ง (HTTPS/TLS) ทุก request ระหว่างมือถือลูกค้า ระบบหลังบ้าน และหน้าจอบาริสต้า
- จำกัดสิทธิ์การเข้าถึงข้อมูลออเดอร์/session ให้เฉพาะระบบและพนักงานที่จำเป็นต้องใช้งานเท่านั้น (least privilege)
- ไม่จัดเก็บข้อมูลระบุตัวตนที่ไม่จำเป็น (เช่น ไม่บันทึกชื่อ-เบอร์โทร) ตามหลัก data minimization
- มีกระบวนการลบ/anonymize ข้อมูลอัตโนมัติเมื่อครบระยะเวลาการเก็บที่กำหนดไว้

### ข้อควรระวังเชิงกฎหมายสำหรับอนาคต (นอก scope รอบนี้)

- หากในอนาคตเพิ่มการเก็บเบอร์โทรศัพท์ หรือระบบสมาชิก/สะสมแต้ม จะถือเป็นข้อมูลส่วนบุคคลที่ต้องขอ **ความยินยอม (consent)** อย่างชัดเจนแยกต่างหากจากฐาน contract/legitimate interest ที่ใช้อยู่ในปัจจุบัน พร้อมต้องมีกลไกให้ลูกค้าถอนความยินยอมและจัดการสิทธิของตนเองได้ (self-service DSAR) ก่อนเปิดใช้งานฟีเจอร์ดังกล่าว

## Scope

**In scope (รอบนี้):**
- เปิดเมนูผ่าน QR code ที่โต๊ะ
- เลือกสินค้า/ตัวเลือก ใส่ตะกร้า ยืนยันคำสั่งซื้อ
- ส่งออเดอร์ไปฝั่งร้านแบบเรียลไทม์ และแสดงสถานะออเดอร์ให้ลูกค้าเห็น

**Out of scope (รอบนี้):**
- การชำระเงินออนไลน์ผ่านระบบ (ยังจ่ายที่เคาน์เตอร์ หรือพนักงานมาเก็บเงินที่โต๊ะ)
- ระบบสมาชิก/สะสมแต้ม
- การสั่งอาหารหรือสินค้าอื่นนอกเหนือจากเครื่องดื่ม
- การเก็บข้อมูลที่ต้องขอความยินยอม (consent) เช่น เบอร์โทรศัพท์/บัญชีสมาชิก (ดูหัวข้อ PDPA ด้านบน)
- ระบบ self-service ให้ลูกค้าจัดการสิทธิของตนเองผ่านหน้าเว็บ (รอบนี้ให้ติดต่อผ่านพนักงาน/ร้านก่อน)

## สมมติฐาน (Assumptions)

- ยังไม่รวมการชำระเงินออนไลน์ในรอบนี้ — ใช้วิธีจ่ายเงินแบบเดิมของร้าน
- ลูกค้าสั่งแบบ guest ไม่ต้อง login หรือสมัครสมาชิกก่อนสั่ง
- แต่ละโต๊ะมี QR code เฉพาะของตัวเองติดถาวรอยู่แล้ว (ไม่ต้องออกแบบขั้นตอนติดตั้ง QR code ใหม่ทุกครั้ง)
- สมมติระยะเวลาเก็บ session/device identifier ไว้ไม่เกิน 24 ชั่วโมงหลังปิดรอบโต๊ะ และเก็บประวัติคำสั่งซื้อ (ไม่รวมข้อมูลเชื่อมโยงตัวตน) ไว้ไม่เกิน 2 ปีเพื่อวัตถุประสงค์ทางบัญชี/วิเคราะห์ยอดขาย — ตัวเลขจริงต้องยืนยันกับเจ้าของร้าน/ฝ่ายกฎหมายอีกครั้ง
- ช่องทางใช้สิทธิของเจ้าของข้อมูล (ขอเข้าถึง/ลบ/คัดค้าน) ในรอบนี้ใช้วิธีติดต่อพนักงานหน้าร้านหรือช่องทางที่ระบุใน Privacy Notice ยังไม่ทำระบบ self-service แยก
